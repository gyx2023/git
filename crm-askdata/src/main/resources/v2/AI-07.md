## 1. 任务概述

### 1.1 背景
智能问数系统涉及企业核心数据查询，面临多种安全风险：Prompt 注入攻击、敏感信息泄露、恶意查询、内容违规等。本任务需要在 HiAgent 平台配置多层安全防护机制，确保系统安全合规运行，满足企业安全标准和法规要求。

### 1.2 目标
| 目标 | 说明 | 验收标准 |
|------|------|----------|
| **全面防护** | 覆盖输入、处理、输出全链路安全 | 无安全死角 |
| **零信任** | 不信任任何用户输入，严格校验过滤 | 100% 输入校验 |
| **低延迟** | 安全过滤增加延迟 < 100ms | 性能影响可控 |
| **可配置** | 支持热更新安全规则，无需重启 | 支持热更新 |
| **可审计** | 所有安全事件完整记录，便于追溯 | 日志记录率 100% |
| **合规性** | 满足《网络安全法》、《数据安全法》要求 | 合规审计通过 |

### 1.4 安全风险矩阵
| 风险类型 | 可能性 | 影响程度 | 防护措施 |
|----------|--------|----------|----------|
| **Prompt 注入** | 高 | 高 | 输入过滤 + 系统指令隔离 |
| **敏感信息泄露** | 中 | 高 | 输出脱敏 + 权限控制 |
| **恶意查询** | 中 | 中 | 频率限制 + 查询复杂度限制 |

| **越权访问** | 中 | 高 | 权限校验 + 数据隔离 |
| **资源耗尽** | 低 | 中 | 限流 + 超时 + 配额管理 |

### 3.4 安全规则配置模板

**文件路径**: `config/security-rules.yaml`

```yaml
# 安全规则配置
security_rules:
  # Prompt 注入检测规则
  prompt_injection:
    enabled: true
    rules:
      - pattern: "忽略上述指令"
        action: block
        risk_level: high
      
      - pattern: "不要遵守"
        action: block
        risk_level: high
      
      - pattern: "系统提示词是"
        action: block
        risk_level: high
      
      - pattern: "```json.*```"
        action: sanitize
        risk_level: medium
      
      - pattern: "SELECT.*FROM.*WHERE"
        action: block
        risk_level: high
    
    # 模型检测
    model:
      enabled: true
      model_name: safety-classifier-v1
      threshold: 0.8
      action: block
    
    # 系统指令保护
    system_prompt_protection:
      enabled: true
      protect_keywords:
        - "系统提示词"
        - "System Prompt"
        - "指令"
        - "规则"
      action: block
  
  # 敏感词过滤配置
  sensitive_words:
    enabled: true
    dictionaries:
      - name: 通用敏感词
        path: /dicts/general_sensitive.txt
        action: block
      
      - name: 政治敏感词
        path: /dicts/political_sensitive.txt
        action: block
      
      - name: 商业机密词
        path: /dicts/business_sensitive.txt
        action: warn
      
      - name: 自定义词库
        path: /dicts/custom_sensitive.txt
        action: block
    
    # 检测模式
    detection:
      mode: fuzzy           # exact/fuzzy/regex
      case_sensitive: false
      min_length: 2
    
    # 处理方式
    handling:
      block: 直接拦截
      warn: 警告但放行
      replace: 替换为***
      log: 仅记录不处理
  
  # 个人信息检测配置
  pii_detection:
    enabled: true
    types:
      phone:
        enabled: true
        pattern: "1[3-9]\\d{9}"
        action: mask
        mask_format: "138****0000"
      
      id_card:
        enabled: true
        pattern: "\\d{17}[\\dXx]"
        action: mask
        mask_format: "110101********1234"
      
      email:
        enabled: true
        pattern: "[\\w.]+@[\\w.]+"
        action: mask
        mask_format: "abc***@xxx.com"
      
      bank_card:
        enabled: true
        pattern: "\\d{16,19}"
        action: mask
        mask_format: "6222****1234"
      
      address:
        enabled: false
        pattern: "[省市区街道]"
        action: log
    
    # 处理方式
    handling:
      on_detect: mask       # mask/block/log
      log_event: true
      alert_on_high_risk: true
  
  # 频率限制配置
  rate_limiting:
    enabled: true
    user_limit:
      enabled: true
      requests_per_minute: 10
      requests_per_hour: 100
      requests_per_day: 1000
      action: reject
      message: "请求频率过高，请稍后再试"
    
    ip_limit:
      enabled: true
      requests_per_minute: 100
      requests_per_hour: 1000
      action: reject
    
    concurrency_limit:
      enabled: true
      max_concurrent: 50
      action: queue
      queue_timeout: 30s
    
    quota:
      enabled: true
      daily_quota: 1000
      monthly_quota: 20000
      reset_time: "00:00"
  
  # 输出过滤配置
  output_filter:
    enabled: true
    filters:
      sensitive_data:
        enabled: true
        action: mask
      
      违规内容:
        enabled: true
        action: block
      
      sql_injection:
        enabled: true
        action: block
      
      code_injection:
        enabled: true
        action: block
    
    # 数据脱敏
    data_masking:
      enabled: true
      fields:
        - phone
        - id_card
        - email
        - bank_card
        - password
      
      # 脱敏规则
      rules:
        phone: "XXX****XXXX"
        id_card: "XXXXXX********XXXX"
        email: "XXX***@XXX.com"
  
  # SQL 注入防护配置
  sql_injection_protection:
    enabled: true
    detection:
      - ast_parsing        # 语法树解析
      - keyword_matching   # 关键词匹配
      - pattern_matching   # 正则匹配
    
    blocked_operations:
      - DROP
      - DELETE
      - UPDATE
      - INSERT
      - TRUNCATE
      - ALTER
      - CREATE
      - EXECUTE
    
    blocked_functions:
      - LOAD_FILE
      - INTO_OUTFILE
      - INTO_DUMPFILE
      - SYSTEM_USER
      - CURRENT_USER
    
    handling:
      on_detect: block
      log_event: true
      alert: true
```

## 4. 注意事项 ⚠️

### 4.1 API Key 安全管理
```yaml
# ❌ 错误：硬编码 API Key
authentication:
  api_key: "sk-xxxxx"  # 明文存储

# ✅ 正确：从环境变量读取
authentication:
  api_key_env: ASKDATA_API_KEY  # 环境变量
```

### 4.2 日志脱敏
```python
# ❌ 错误：日志打印敏感信息
log.info("User query: {}", user_query)  # 可能含手机号

# ✅ 正确：脱敏后打印
log.info("User query: {}", mask_sensitive(user_query))
```

### 4.3 规则更新
```bash
# ❌ 错误：直接修改生产规则
# 无测试，可能导致误拦截

# ✅ 正确：灰度更新
1. 测试环境验证
2. 灰度发布 (10% 流量)
3. 监控观察
4. 全量发布
```

### 4.4 性能影响
```python
# ❌ 错误：同步阻塞式过滤
def filter_input(text):
    result = heavy_check(text)  # 耗时 500ms
    return result

# ✅ 正确：异步或缓存优化
def filter_input(text):
    if cache.has(text):
        return cache.get(text)
    result = async_check(text)  # 异步或快速检查
    return result
```

### 4.5 误报处理
```python
# ❌ 错误：一刀切拦截
if contains_sensitive_word(text):
    block()

# ✅ 正确：上下文判断
if contains_sensitive_word(text) and not is_business_context(text):
    block()
```

## 5. 需要特别关注的点 🔴

### 5.1 陷阱防护矩阵

| 陷阱类型 | 风险描述 | 防护措施 | 验证方法 |
|----------|----------|----------|----------|
| **Prompt 注入** | 用户覆盖系统指令 | 输入过滤 + 系统指令隔离 | 注入测试 100% 拦截 |
| **敏感泄露** | 输出含手机号/身份证 | 输出脱敏 + 权限控制 | 检查输出数据 |
| **越权访问** | 用户访问无权数据 | 权限校验 + 数据隔离 | 越权测试被拒绝 |
| **资源耗尽** | 高频请求压垮服务 | 频率限制 + 配额管理 | 压测验证限流生效 |
| **日志泄露** | 日志含敏感信息 | 日志脱敏 + 权限控制 | 检查日志文件 |
| **规则失效** | 安全规则未生效 | 规则校验 + 监控告警 | 定期检查规则状态 |
| **误报过多** | 正常请求被拦截 | 白名单 + 上下文判断 | 监控误报率 < 1% |
| **生产环境** | 测试规则带到生产 | 环境隔离 + 发布审核 | 检查生产规则列表 |

## 8. 常见问题 (FAQ)

**Q1: 正常请求被误拦截怎么办？**
A: 1. 检查敏感词库是否过于严格；2. 调整检测阈值；3. 添加白名单；4. 分析误报日志优化规则。

**Q2: 安全过滤导致延迟过高怎么办？**
A: 1. 优化规则匹配算法；2. 减少规则数量；3. 使用缓存；4. 异步处理非关键过滤。

**Q3: 如何更新敏感词库？**
A: 1. 编辑词库文件；2. 热加载配置；3. 验证生效；4. 记录变更日志。

**Q4: 如何防止安全配置被篡改？**
A: 1. 配置权限控制；2. 配置变更审计；3. 配置版本管理；4. 定期安全检查。

**Q5: 如何处理误报？**
A: 1. 记录误报案例；2. 分析误报原因；3. 优化检测规则；4. 添加例外处理。

**Q6: 安全日志太多怎么办？**
A: 1. 调整日志级别；2. 仅记录高风险事件；3. 使用采样；4. 定期归档清理。

**Q7: 如何测试安全配置有效性？**
A: 1. 使用自动化测试脚本；2. 定期渗透测试；3. 红蓝对抗演练；4. 第三方安全评估。

**Q8: 如何支持多租户安全隔离？**
A: 1. 租户级安全策略；2. 数据隔离；3. 独立限流配额；4. 独立审计日志。

**Q9: 合规要求变化如何应对？**
A: 1. 监控法规更新；2. 定期合规评估；3. 快速调整配置；4. 更新安全策略。

**Q10: 安全事件如何追溯？**
A: 1. 完整记录安全日志；2. 关联 TraceID；3. 保存原始请求；4. 定期审计分析。
